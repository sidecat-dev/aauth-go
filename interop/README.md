# Independent interoperability evidence

`elixir-agent-request.json` is generated by the independent Elixir AAuth
implementation in `sidecat-beam`. The vector contains an Elixir-minted
`aa-agent+jwt`, an Elixir-serialized `AAuth-Mission` reference, and an
Elixir-created RFC 9421 request signature using the JWT Signature-Key scheme.
The Go test reconstructs the HTTP request from those exact wire values and
verifies issuer trust, token claims, confirmation-key binding, required
component coverage, signature freshness, mission syntax, and the Ed25519
signature. Mutation controls prove that changing the mission or Signature-Key
breaks verification.

The fixture records the exact `sidecat-beam` commit that generated it. To
regenerate from a checked-out copy at that commit:

```sh
cd /absolute/path/to/sidecat-beam
mix run /absolute/path/to/aauth-go/interop/generate_elixir_agent_request.exs \
  /absolute/path/to/aauth-go/interop/elixir-agent-request.json
```

The generator reads the comparator commit itself and refuses tracked changes
to its AAuth source or dependency files, so the recorded revision identifies
the code that actually emitted the vector.

`go-agent-request.json` proves the reciprocal direction. It is generated
entirely through the public Go package:

```sh
go run ./internal/interop/cmd/generate interop/go-agent-request.json
```

Run the independent Elixir verifier from the checked-out `sidecat-beam`
implementation:

```sh
cd /absolute/path/to/sidecat-beam
mix run /absolute/path/to/aauth-go/interop/verify_go_agent_request.exs \
  /absolute/path/to/aauth-go/interop/go-agent-request.json
```

That verifier checks the Go-minted agent token with the Elixir token
implementation, binds its confirmation key, verifies the Go-created HTTP
signature and mission reference, and runs the same two mutation controls. The
Go generator itself has an executable test which verifies its emitted request
before it becomes comparator input.

This is implementation-to-implementation evidence, not an expected value
transcribed from draft prose. It proves the selected request profile in both
directions. It does not claim every token, Signature-Key scheme, HTTP
component, response, or server role interoperates.
